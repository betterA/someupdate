笔记 × Agent

一个本地 Web 端：在笔记的任务行上直接派活给 Agent，进度和结论回到这一行。
只接 opencode 和 dsh 两个 CLI，只服务一个人，一条命令启动，零数据库。

借鉴 obsidian-agent-deck 的「任务行委派 + 写回」内核 形态 本地 Web · 127.0.0.1 范围 设计稿，不含实现
01

设计取舍

个人工具，减法比加法重要

PRINCIPLE 01

笔记是唯一的数据

笔记就是本地 .md 文件。人写的和 Agent 写回的落在同一份文件里，关掉服务仍能用任何编辑器打开、能进 Git、能直接被 Obsidian 接管。

PRINCIPLE 02

不追踪，只发起

状态来自自己启动的进程，而不是去解析各家的会话数据库。不扫描 ~/.dsh/sessions 的 zstd 日志，也不读 opencode 的 SQLite。

PRINCIPLE 03

一屏完成一次委派

写一行 → 选 Agent → 发送 → 看结果写回。没有确认弹窗、没有拖拽、没有设置向导；误发随时 Stop。

Agent Deck 的做法本设计理由
任务行即委派入口，行尾把手 / @agent保留 · 核心把「记录」和「派活」合成一个动作，是整个项目值得借鉴的唯一内核。
状态 pill + 结论写回同一行保留 · 简化只留 5 个状态；结论 ≤ 240 字写进缩进子块，原文另存文件。
上下文：母项链 + 当前项子树保留派活时自动带上上级标题和子项，不带兄弟项；一行下拉可改范围。
扫描 7 类客户端本地会话日志 / SQLite / zstd砍掉个人用只关心自己从笔记发起的 run；扫描是全部复杂度和脆弱性的来源。
拖拽绑定会话 ↔ 任务、deeplink 跳客户端砍掉没有「外部会话」这个概念，自然不需要绑定。续聊走 CLI 的 --continue / --resume。
DOING / TOREVIEW / PAUSED / DONE 任务关键词体系砍掉状态由编辑器装饰层渲染 + 隐藏锚点保存，不污染正文 Markdown。
菜单栏、Dreaming、长期记忆、整理模板、双语、统计面板砍掉一个人的工具不需要回顾体系和可配置性，默认值定死就好。
模型 / 推理强度 / 权限模式分层设置收敛放进一个配置文件，界面只留「谁执行、能不能改文件」两个开关。

03

委派与回流

从一行字到一段结论，四次状态变化

01 / WRITE

写一行

在笔记里写 - TODO …，光标停在这一行。子项与上级标题自动成为上下文。

02 / SEND

⌘↵ 派活

行尾浮层选 opencode / dsh，确认上下文范围，回车即发；不弹二次确认。

03 / WATCH

看进度

行尾 pill 变蓝并计时，右侧卡片滚动流式输出；长任务可切到别的笔记继续写。

04 / WRITE BACK

结论回行

完成后在任务行下插入子块：结论 / 改动 / 未完成；完整原文归档到 .agent/runs/。

排队→ 运行中→ 待确认↘ 完成 /失败 /已停止 每个 Agent 同时 1 个任务，全局最多 2 个并行，超出排队

上下文规则沿用借鉴项目：取母项链文本 + 当前项及其子树，不带兄弟项；已有写回块作为上一轮结论一并附上。

写回 · 原文与正文分离

# 用户正文（保持原样）
- TODO 整理 TC-05.5 信号分组 @dsh
  <!-- run: 20261115-1552-dsh-a1b2 -->
  - 🤖 15:52–15:54 · dsh
    结论：三组信号可按「组→信号→timing」
    两级随机抽取，每轮 1–2 组，与 power cycle
    对齐后注入 PRBS，覆盖 27 个用例无重复。
    改动：无（只读分析）
    未完成：timing 取值范围需人工确认
    ↳ 原文 .agent/runs/20261115-1552-dsh-a1b2.md

# 隐藏锚点只存元数据；pill / 按钮由编辑器渲染
# 文件级串行写入队列，写前重读磁盘合并手写改动
  • 幂等：同一 runId 只更新自己的子块，重跑生成新块，不覆盖上一轮。
  • 不覆盖：写回前重读文件，按锚点定位插入；用户在 Agent 跑动期间手写的任何内容都保留。
  • 不截断：≤ 240 字是结论长度，完整 stdout / 事件流另存 .md，链接可点开。
  • 不额外调模型：结论由委派提示词末尾固定的一句格式要求产出（「最后用 3 行写：结论 / 改动 / 未完成」），直接截取该段写回；超长或缺失时退化为「查看原文」链接，不引入第二个 LLM 调用。

// config.json · 只有这些
{
  "vault": "~/notes/vault",
  "defaultAgent": "opencode",
  "agents": {
    "opencode": { "bin": "opencode", "model": "" },

适配层契约 · 加第三个 Agent 只改这里

interface AgentAdapter {
  id: 'opencode' | 'dsh'
  spawn(req: RunRequest): ChildProcess
  parse(line: string): AgentEvent | null
  stop(proc: ChildProcess): void
  resumeRef(proc): string        // 续聊用
}

type AgentEvent =
  | { t:'delta',  text: string }
  | { t:'tool',   name: string, detail: string }
  | { t:'need_ok', prompt: string }
  | { t:'done',   text: string }
  | { t:'error',  message: string }

两个 CLI 的输出差异全部消化在 parse() 里，UI 与写回器只认统一事件。借鉴项目的接入原则同样适用：必须有能非交互跑完的 CLI，否则不接。

实际命令

# opencode：NDJSON 事件流，逐行解析
opencode run --format json \
  --dir <vault> --model <provider/model> \
  "<prompt>"
# 续聊：--continue / --session <id>
# 不传 --auto：默认拒绝权限请求

# dsh：headless 一次性任务
dsh --profile headless "<prompt>"
# 或 dsh run --task-file / --profile
# status / log / stop 作为兜底探测
差异点处理方式
opencode 结构化事件逐行 NDJSON → delta / tool / done
dsh 输出格式不稳定默认按文本流 + 退出码；支持 JSON 时只改 adapter
权限 / yolo默认只读；写文件需单次显式勾选，绝不默认全自动
取消SIGTERM → 状态置 stopped，保留已收到的输出
06

范围边界

写清楚不做什么，比写清楚做什么更重要

MVP · 只做这些
  • 笔记的新建 / 打开 / 搜索 / 编辑 / 自动保存（纯 .md）
  • Markdown 编辑器 + 任务行装饰（状态 pill、委派按钮、写回块）
  • 从任务行委派，上下文三档范围可选
  • opencode / dsh 两个 adapter，流式输出、停止、重跑、续聊
  • 结论写回 + 原文归档，手写内容零覆盖
  • 甲板 2 张卡 + 最近运行列表
  • 设置抽屉 4 项（CLI 路径 / 默认 Agent / 工作目录 / 写权限），超时等冷参数只放 config.json；快捷键 3 个：⌘↵ 委派 / ⌘K 搜索 / ⌘\ 收起甲板
明确不做
  • 账号 / 登录 / 云同步 / 多用户 / 权限体系
  • 数据库、全文索引、向量检索、RAG
  • 扫描外部客户端会话、deeplink、桌面端跳转
  • 富文本块编辑器、双向链接、图谱、插件市场
  • 菜单栏常驻、统计看板、长期记忆 / Dreaming、整理模板
  • 多语言、主题切换、协作、移动端适配
  • 第三个 Agent —— 接口留好，但当前不接
两个默认假设（已按此设计，实现前验证即可，不阻塞）
  • dsh 输出：假设 headless 模式的 stdout 是文本流 + 退出码；若它提供结构化事件，只在 dsh.parse() 内部替换，UI 不变。
  • 写权限：假设默认让 Agent 只读分析笔记库，需要它改文件时在浮层单次授权；工作目录始终锁定 vault，不开放任意路径。
